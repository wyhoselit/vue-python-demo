# OpenTelemetry Metrics Reference

This document describes all metrics collected by the OpenTelemetry instrumentation in this system.

## Backend Metrics {exported_job="backend-service"}

### HTTP Server Metrics

| Metric | Type | Description |
|--------|------|-------------|
| `http_server_duration_milliseconds` | Histogram | Duration of inbound HTTP requests in milliseconds. Bucketed by status code and endpoint. |
| `http_server_active_requests` | Gauge | Number of currently active HTTP requests. |
| `http_server_request` | Counter | Total number of HTTP requests received. |
| `http_server_response` | Counter | Total number of HTTP responses sent. |

### Alert Rules

- **HighBackendLatency**: `histogram_quantile(0.95, sum(rate(http_server_duration_milliseconds_bucket{job="backend-service"}[5m])) by (le, job)) > 200`
  - Triggers when 95th percentile latency exceeds 200ms for 2 minutes.
- **TooManyActiveBackendRequests**: `sum(http_server_active_requests{job="backend-service"}) > 50`
  - Triggers when more than 50 requests are active simultaneously for 5 minutes.
- **HighErrorRate**: `rate(http_server_duration_milliseconds_count{status=~"5.."}[5m]) > 0.05`
  - Triggers when error rate exceeds 5% for 1 minute.
- **ServiceDown**: `up == 0`
  - Triggers when the service is completely down for 1 minute.

## Frontend Metrics (exported_job="frontend-app")

### User Interaction Metrics

| Metric | Type | Description |
|--------|------|-------------|
| `frontend_app_page_view_total` | Counter | Total number of page views by route name. |
| `frontend_app_button_click_total` | Counter | Total number of button clicks by element ID. |
| `frontend_app_form_submit_total` | Counter | Total number of form submissions by form name. |

### Performance Metrics

| Metric | Type | Description |
|--------|------|-------------|
| `frontend_app_component_render_duration_milliseconds` | Histogram | Duration of component rendering in milliseconds, bucketed by component name. |
| `http_client_duration_milliseconds` | Histogram | Duration of HTTP client requests from frontend to backend, bucketed by URL and status code. |

### Alert Rules

- **SlowComponentRender**: `histogram_quantile(0.95, sum(rate(frontend_app_component_render_duration_milliseconds_bucket[5m])) by (le, component_name)) > 500`
  - Triggers when component rendering exceeds 500ms (p95) for 5 minutes.
- **PageViewDrop**: `increase(frontend_app_page_view_total{job="frontend-app"}[10m]) < 1`
  - Triggers when no page views occur in the last 10 minutes.
- **HighFrontendClientLatency**: `histogram_quantile(0.95, sum(rate(http_client_duration_milliseconds_bucket{job="frontend-app"}[5m])) by (le, http_url)) > 1000`
  - Triggers when frontend API calls exceed 1s (p95) for 2 minutes.
- **NoLoginButtonClicks**: `increase(frontend_app_button_click_total{element_id="login-submit"}[15m]) == 0`
  - Triggers when the login button hasn't been clicked in 15 minutes.

## Metric Standards

All metrics follow [OpenTelemetry Semantic Conventions](https://github.com/open-telemetry/opentelemetry-specification/blob/main/specification/metrics/semantic_conventions/). 

- Backend metrics are automatically generated by `prometheus-fastapi-instrumentator`
- Frontend metrics are generated by `@opentelemetry/instrumentation-document-load` and `@opentelemetry/instrumentation-user-interaction`

**Do not rename these metrics.** They are standardized for compatibility with Grafana dashboards and observability tools.

## Adding Custom Metrics

To add business-specific metrics (e.g., `order_created_total`):

1. Use `meter.createCounter()` or `meter.createHistogram()` in your code
2. Use descriptive names following the convention: `{domain}_{action}_{unit}`
3. Add appropriate labels (e.g., `status`, `type`, `environment`)
4. Add corresponding alert rules in `alerts.yml`

Example:
```python
from opentelemetry import metrics

meter = metrics.get_meter("myapp")
order_counter = meter.create_counter("order_created_total")
order_counter.add(1, {"status": "success", "payment_method": "credit_card"})
```

**Note**: Custom metrics are not subject to semantic conventions and can be named freely.
