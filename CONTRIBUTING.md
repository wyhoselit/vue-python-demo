# Contributing

## Code Review Process

All changes must be submitted via pull request and require at least one approval from a core contributor before merging.

### The Author's Responsibility
- **Create a clear PR:** The title and description should clearly explain the "what" and "why" of the change. Link to any relevant issues.
- **Self-review:** Review your own code first. Leave comments to explain complex parts or to guide the reviewer's attention.
- **Ensure tests pass:** All CI checks must be green. This includes tests, linting, and type-checking.
- **Respond to feedback:** Address comments and questions from reviewers in a timely manner.

### The Reviewer's Responsibility
- **Be constructive:** Offer clear, actionable feedback.
- **Be thorough:** Review for correctness, performance, security, and adherence to style guides.
- **Be timely:** Aim to review PRs within 24 hours.
- **Approve or Request Changes:** Use GitHub's review tools to either approve the PR or request changes.
